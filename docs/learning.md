# 나만의 기술 노트

## 기술: 요일·시간 문자열을 "지금 운영 중" 판단으로 바꾸기

### 개념 5개 (Claude 정리)
| # | 개념 | 쉬운 설명 |
|---|---|---|
| 1 | 정규 표현식 | 글자 패턴을 찾는 규칙. `9시-18시`, `09:00~18:00`처럼 모양이 다른 글자에서 숫자만 꺼낼 때 쓴다. |
| 2 | 분 단위 변환 | 시간을 "자정부터 몇 분"으로 바꾸면 비교가 쉽다. 09:30 → 570. |
| 3 | 요일 번호 | JavaScript는 일요일=0, 월요일=1 … 토요일=6. `월~금`은 {1,2,3,4,5}가 된다. |
| 4 | 시간대(타임존) | Vercel 서버는 UTC로 돈다. 한국 시간은 UTC+9라서 직접 9시간을 더해야 "지금"이 맞다. |
| 5 | 읽을 수 없는 값 처리 | 형식을 모르는 값을 "운영 중"으로 추측하지 않고 "확인 필요"로 따로 표시한다. |

### 내 말 요약 (내가 직접 3줄)
1. 쉼터마다 시간을 적는 방식이 달라서, 글자 모양 규칙(정규식)으로 숫자만 뽑아 "몇 분"으로 바꾼 다음 지금 시각과 크기 비교를 한다.
2. 서버는 한국 시간이 아니라서 9시간을 더해 줘야 하고, 안 그러면 아침 10시에 "운영 종료"가 뜨는 식으로 틀린다.
3. 처음 보는 형식은 억지로 맞히지 말고 "확인 필요"로 남기는 게 맞다. 틀린 "운영 중"이 빈칸보다 더 위험하다.

### 예측 후 실행 (④)
- 바꾼 값: 지금 시각을 17:59 → 18:00으로 바꿈 (운영 시간 `월~금 09:00~18:00`, 수요일)
- 내 예측: 18:00까지 운영이니까 18:00에도 "운영 중"일 것이다.
- 실제 결과: 17:59는 `open`, 18:00은 `closed`
- 틀린 지점 = 내가 몰랐던 부분: 코드가 `지금 < 닫는 시각`으로 비교해서 닫는 시각 딱 그 분은 운영 종료로 친다. "~18:00"은 18시에 문을 닫는다는 뜻이라 이게 맞다. 경계값(같을 때)을 포함하는지 안 하는지를 따로 봐야 한다.

### 내가 낸 오류 (⑤)
- 오류 문장: `SyntaxError: The requested module './hours.js' does not provide an export named 'shelterstatus'`
- 고친 방법 한 줄: 함수 이름을 `shelterstatus`로 소문자로 잘못 써서 난 오류라, `export`된 이름 그대로 `shelterStatus`(S 대문자)로 고쳤다.
