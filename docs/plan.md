# 첫 버전 계획 (Plan 모드 결과)

PRD.md(v2)의 핵심 시나리오가 처음부터 끝까지 돌아가는 데 꼭 필요한 것만 계획했습니다.

## 화면 (1개)
| 화면 | 사용자가 하는 일 |
|---|---|
| 쉼터 찾기 (`index.html`) | 행정동을 고른다 → 운영 중 / 운영 종료가 구분된 목록을 본다 → 맨 아래 출처·기준일을 확인한다 |

## 데이터 흐름
```
CSV(data/) → Supabase shelters 테이블 (RLS 켬) → api/shelters.js?dong=○○ → 화면
```
- **Supabase에 넣는 이유**: 연 1회 갱신되는 CSV라 자주 안 바뀐다. 동 조건으로 빠르게 조회할 수 있고 API 한도 걱정이 없다.
- 화면은 Supabase를 직접 부르지 않는다. 서버 함수만 `SUPABASE_SECRET_KEY`로 읽는다.
- "지금 운영 중" 판단은 서버 함수에서 한국 시간 기준으로 한다(`lib/hours.js`).

## 파일 구성
| 파일 | 역할 |
|---|---|
| `index.html` | 화면 (저장소 맨 위) |
| `api/shelters.js` | 동 목록 / 동별 쉼터 + 운영 상태 |
| `lib/hours.js` | 요일·시간 문자열 → 운영 여부 |
| `supabase/schema.sql` | 테이블 생성 · RLS 켜기 |
| `data/` | 원본 · 예시 CSV |

## AI 기능
핵심 시나리오에 없음 → 넣지 않는다.

## 나중에 (핵심 시나리오 밖)
운영 중 정렬 · 가까운 순 정렬 · 지도 · 한파 특보 · AI 안내 문구

## ★ 처음 볼 가능성이 큰 기술
**요일 · 시간 문자열을 "지금 운영 중" 판단으로 바꾸기** (문자열 파싱 + 한국 시간 처리)
→ 2교시 학습 루프의 재료
